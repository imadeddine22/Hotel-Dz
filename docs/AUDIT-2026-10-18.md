# Meskan — QA, security & performance audit (2026-10-18)

Scope: the code on branch `feat/seo-wilayas-e2e-fixes` (commit `a49a7c4` + this audit's changes), tested locally.
Production was touched only with a handful of read-only GET requests (health, 404, one list, headers).

Legend: **Verified** = reproduced by a test or measurement. **Code review** = found by reading the code, not reproduced
against a live system. **Not tested** = see section 13.

---

## 1. Overall health

The core flows work: browsing, search, listing pages, booking requests, owner confirmation, messaging, reviews,
password reset, role-based areas. The API test suite grew from 272 to **292 checks, all passing**.

The audit found one **critical** bug (double booking under concurrent requests) plus several security and
robustness gaps. All of them are **fixed and covered by regression tests**, except the items listed in section 12.
The most important open item is that **uploaded images are written to the Render server's local disk**.

## 2. Architecture (as found in the code)

| Part | What it is |
|---|---|
| Frontend | Next.js 14.2.35 (App Router), React 18, Tailwind, Zustand, axios. Hosted on Vercel (`hotel-dz-three.vercel.app`). fr / ar (RTL) / en via `/ar`, `/en` URL prefixes (middleware rewrite). |
| Backend | Express 4 + Mongoose 8, ESM. Hosted on Render (`backend-yikc.onrender.com`, behind Cloudflare — seen in response headers). |
| Database | MongoDB (Atlas URI in `backend/.env`); local dev and tests use `mongodb-memory-server`, an in-memory database reseeded at every start. |
| Auth | JWT, 7-day expiry, sent both as an httpOnly cookie (`SameSite=None` in production) and as a Bearer token kept in `localStorage`. Passwords hashed with bcrypt (cost 10). | Uploads | multer (memory, 5 MB, `image/*`). **Despite the file name `cloudinaryUpload.js`, files are written to `backend/public/uploads`** and served by Express. |
| Email | nodemailer over SMTP; **SMTP is not configured** (emails are only logged). |
| Payments | **None.** Bookings are paid on site; the owner marks them paid. The old Chargily webhook route is gone (an e2e check verifies this). |
| Translation | MyMemory API for listing text (background; free quota). |

**Production backend is running older code.** Its health message is `DzHotels API is running`, and this branch says `Meskan API…`.
None of the fixes in this report (and none of the recent features) are live until the backend is redeployed.

## 4. Bugs and vulnerabilities found

### Critical

**C1. Double booking under concurrent requests — Verified, fixed.**
- Reproduction: 10 different customers send the same house booking at the same moment → all 10 got `201`. A room type with 3 units accepted 10 bookings.
- Root cause: the code checked availability first and inserted afterwards, with nothing atomic between the two steps (`booking.controller.js`).
- Fix: after inserting, `lostRace()` (`utils/checkAvailability.js`) counts the bookings that hold overlapping dates and were created before this one (`_id` order). When that count already fills the capacity, the new booking is deleted and the request gets `409`. The earliest requests always win, and no locks or transactions are needed (the in-memory dev database has no replica set).
- Regression tests: "8 simultaneous bookings of one house → exactly 1 accepted", "…room type with N units → no overbooking".

### High

**H1. Rate limiting counted every visitor as one IP on Render — Code review, fixed.**
`trust proxy` was not set, so behind Render's proxy and Cloudflare `req.ip` is the proxy's address. The global limit and the
new login limits were therefore shared by the entire audience. A single abuser could get everyone blocked.
Fix: `app.set('trust proxy', TRUST_PROXY)` (default `1` in production). **Verify after deploy** (section 14).

**H2. No protection against password guessing — Code review, fixed.**
Only the global limit applied (300 requests / 15 min). Added `loginLimiter`, which allows 20 failed attempts per IP and per email in 15 minutes.
Successful logins don't count, so many users behind one mobile-carrier IP are not locked out. Also added: a sign-up limit
(50 per hour per IP), a password-reset limit (10 per 15 min) and a contact-form limit (10 per hour).
Regression tests: 21st failed login → `429`, another account still logs in.

**H3. Uploaded images live on the Render server's disk — Code review, NOT fixed.**
`utils/cloudinaryUpload.js` writes into `backend/public/uploads`. Render's filesystem is ephemeral (unless a paid
persistent disk is attached), so listing photos disappear at every redeploy or restart. Cloudinary credentials
exist in `.env`, but the code does not use them. This needs a decision (Cloudinary or a Render disk) before real owners upload photos.

**H4. Vulnerable dependencies — Verified, partly fixed.**
`npm audit fix` (no major upgrades): backend went from 10 findings (1 critical, 3 high) to 3, and the frontend from 6 to 2. Remaining:
- **next 14.2.35**: critical advisory "DoS via Image Optimizer remotePatterns" for *self-hosted* apps, plus PostCSS advisories. Vercel hosting reduces the risk, but the fix needs a major upgrade (Next 15/16).
- **nodemailer 8**: high advisory about the `raw` message option. The code doesn't use `raw`, so it is not exploitable here. Fixed in v10 (major).
- gaxios/uuid (through `google-auth-library`): moderate.

### Medium

| # | Finding | Status |
|---|---|---|
| M1 | `?limit=0` (or a negative value) returned **every** record; `page=abc` gave `pages: null`. Verified on production too (`/hotels?limit=0`). | Fixed: `utils/query.js` `paging()`, cap 50 (admin 100). |
| M2 | Non-numeric filters crashed with `500`: `?minStars=abc`, `?minPrice=abc`, `?priceRanges[0][x]=1` ("r.split is not a function"). Verified on production (`/hotels?minStars=abc` → 500). | Fixed: `num()` parsing; `CastError` → `400`. |
| M3 | Query operators from the URL reached MongoDB (`?type[$ne]=x`). Impact was limited (public lists always force `status: 'approved'`), but there was no general protection. | Fixed: `sanitize.middleware.js` strips `$`/`.`/`__proto__` keys from query, body, params. | M4 | A request from an unknown `Origin` crashed with `500` instead of being refused. | Fixed: `403`. Refusal is kept on purpose: with `SameSite=None` cookies it also blocks cross-site form posts (CSRF). |
| M5 | The frontend sent no security headers (no anti-framing, no `nosniff`, no referrer policy). Verified on production. | Fixed in `next.config.mjs`: `X-Frame-Options`, `CSP: frame-ancestors 'self'`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`; `X-Powered-By` removed. |
| M6 | In production, `500` responses carried internal error text (e.g. Mongoose cast messages). Verified on production. | Fixed: generic "Server error" in production (detail still logged server-side). |
| M7 | Contact form: no validation, unlimited message size, no spam limit. | Fixed: Joi schema (lengths, email) + `contactLimiter`. |
| M8 | Global limit of 300 requests / 15 min per IP is low for real users (one page view = 5–15 API calls; Algerian mobile carriers share IPs). The test suite itself hit it. | Raised to 1000, tunable with `RATE_LIMIT_MAX`. |
| M9 | Home page layout shift on mobile, measured **CLS 0.255** ("poor") on a production build. Main source: the hero's quick-search chips switched from Latin to Arabic after the commune list loaded in the browser. | Partly fixed: those names are now in the base dictionary, so the server renders them in Arabic. **Re-measure after deploy.** |

## 8. Load test

- **Environment:** Windows laptop. The API runs `dev:local` (single Node 22 process, **in-memory MongoDB**, demo data: 4 hotels, 6 houses, 8 sales), and the load generator runs on the **same machine**. `RATE_LIMIT_MAX` was raised so the limiter would not cap the test.
- **Endpoints:** 18 read-only public endpoints (lists, search, details, rooms, wilayas, testimonials). 15 s per stage.

| VUs | requests | req/s | p50 | p90 | p95 | max | errors |
|---|---|---|---|---|---|---|---|
| 1 | 1 512 | 100.8 | 9 ms | 14 ms | 15 ms | 55 ms | 0 % |
| 5 | 2 348 | 156.4 | 31 ms | 43 ms | 46 ms | 152 ms | 0 % |
| 10 | 2 480 | 164.8 | 55 ms | 79 ms | 86 ms | 894 ms | 0 % |
| 25 | 2 860 | 189.3 | 128 ms | 190 ms | 206 ms | 309 ms | 0 % |
| 50 | 2 585 | 170.2 | 280 ms | 380 ms | 396 ms | 687 ms | 0 % |

Recovery after the test: `/health` answered 200 in 2 ms. Throughput plateaus at ~170–190 req/s, the ceiling of one
Node process on this machine; latency then grows linearly with concurrency. Each endpoint alone answers in 5–12 ms
(median), so no single slow query stands out.

**Limitations:** these numbers say nothing about Render/Atlas capacity. Production adds network latency and Render's
instance size (free instances also sleep and cold-start), and Atlas tier limits apply. No test was run against production.

## 9. Security findings — status summary

| Area | Result |
|---|---|
| Authentication / sessions | JWT httpOnly cookie + bearer; tokens revoked after password change (`passwordChangedAt`); reset tokens hashed, single-use, 30 min. ✔ Brute force limit added (H2). |
| Access control / IDOR | Reviewed bookings, conversations, reviews, rooms, houses, hotels, sales, seller, admin routes: ownership checked server-side everywhere. Browser and e2e confirm 403s. ✔ |
| NoSQL injection | Fixed globally (M3). Login/register were already protected by Joi. |
| XSS | React escapes output; JSON-LD is escaped; no `dangerouslySetInnerHTML` with user data. Emails fixed (L3). ✔ |
| CSRF | The cookie is `SameSite=None`, but cross-origin requests are refused by the CORS check (M4) and the API takes JSON. Keep the 403 refusal. |
| File uploads | `image/*` only, 5 MB, file names are generated server-side, extension comes from an allow-list (an SVG would be saved as `.jpg`), and helmet sends `nosniff`. No path traversal. ⚠ Storage is ephemeral (H3). |
| Secrets | None in the frontend bundle or git (`.env` files are git-ignored). Not checked: Render/Vercel dashboards. |
| CORS / headers | Fixed (M4, M5). Helmet on the API (CSP disabled there: the API serves no HTML). |
| Rate limits | Fixed (H1, H2, M7, M8). |
| Dependencies | Partly fixed (H4). |
| Payments / webhooks | Not applicable — no online payment exists. |
